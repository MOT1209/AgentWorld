3 نقاط القوة (تُحفظ وتُبنى عليها)

✔الـ ledger أحادي الكاتب بسبع ضمانات موثقة ومختبرة بالسباقات — packages/economy/src/ledger.service.ts. هذا أثمن أصل في المشروع.
✔نقطة إنفاذ واحدة للأدوات: lookup ← audience ← permission ← Zod ← approval ← execute ← audit — packages/tools/src/executor.ts. لا يوجد باب خلفي.
✔السلوك من الدور لا الاسم: لا يوجد if (agent.name === ...) في المستودع كله، والسجل يرفض الأدوار ذات الصلاحيات البشرية.
✔إعادة تشغيل الموافقات أحادية الطيران (claimForExecution) — مستحيل تنفيذ مزدوج لموافقة واحدة.
✔حظر المراجعة الذاتية + ميزانية rework في حلقة المراجعة — تصميم ناضج نادر في مشاريع الهواة.
✔فصل المحاكاة عن التنفيذ كمبدأ معلن وموثق — أساس Phase 3 الصحيح.
✔عزل بيئة الاختبار لكل عملية (test-<pid>.db) — حل جذري لمشكلة فساد التشغيلات المتزامنة.
✔انضباط TypeScript صارم (noUncheckedIndexedAccess + منع any) وESLint نظيف بدون أخطاء.
✔التوثيق يعيش مع الكود: 7 وثائق + تعليقات معمارية داخل الملفات تشرح «لماذا» لا «ماذا».

4 الملاحظات مرتبة بالخطورة

كل ملاحظة: الموقع الدقيق، الأثر، والإصلاح المقترح.

حرجة H-1: محرك السياسات كود ميت — نظامان متوازيان للموافقات

يوجد packages/approvals/src/policy-engine.ts (محرك ALLOW/REQUIRE_APPROVAL/DENY أنيق) لكن لا يستدعيه أحد — الـ ToolExecutor يستخدم approval-policy.ts القديم. أي تعديل مستقبلي على المحرك الجديد لن يغير سلوك النظام، وأي قارئ سيظن العكس. الأثر: التباس معماري + خطر انحراف القواعد.

🔧 الإصلاح: قرار واحد موثق — إما توصيل المحرك مكان evaluateApproval مع اختبارات تكافؤ، أو حذف الملف. لا يبقى الاثنان معًا.

حرجة H-2: الجلسات سجلات بلا runtime — runAgent لا يعرفها

خدمة packages/runtime/src/session.service.ts ممتازة، لكن حلقة الوكيل في packages/agents/src/runtime.ts لا تنشئ صف AgentSession ولا تحدثه ولا تنهيه. النتيجة: لوحة المراقبة ستعرض جلسات فارغة دائمًا، وSESSION_STARTED/FINISHED لا تُنشر من المسار الحقيقي.

🔧 الإصلاح: تغليف runAgent بفتح/تحديث/إنهاء الجلسة في agent-orchestrator.ts (بدون تعديل الحلقة نفسها)، مع اختبار تكامل يثبت ظهور الجلسة.

عالية H-3: جدول AgentHierarchy لا يُكتب أبدًا

التصعيد يُوجَّه عبر RoleProfile.reportsTo (بيانات ثابتة) بينما جدول التسلسل في قاعدة البيانات فارغ دائمًا — تحقق: لا يوجد أي agentHierarchy.create في الحزم. التصميم المُعلن «التسلسل بيانات» غير متحقق.

🔧 الإصلاح: إما مزامنة الصفوف من reportsTo عند الإقلاع/البذر، أو حذف الجدول والاعتراف بأن التسلسل role-based. القرار يُوثق في docs/ARCHITECTURE.md.

عالية H-4: خدمات التنسيق بلا واجهات — مخزون ميت للمستخدم

توجد مسارات /plans فقط. لا مسارات لـ sessions/reviews/reports/escalations/conflicts، ولا شاشات dashboard لها، ولا بذر تجريبي، ولا اختبارات API لها. المستخدم (والبشر) لا يستطيع رؤية أو تشغيل 60% من Phase 2.

🔧 الإصلاح: routers رفيعة (نفس نمط plan.routes.ts) + 3 شاشات + بذر + اختبارات تكامل. جهد متوسط، قيمة عالية.

عالية H-5: لا CI — البوابة الخضراء يدوية

لا يوجد .github/workflows. كل التحقق (typecheck/lint/test/build) يعتمد على انضباط بشري، وقد رأينا كسر typecheck يُدفع للشجرة. cubefarm المرجعي لديه CI لكل PR.

🔧 الإصلاح: workflow واحد verify على ubuntu + windows (مع متغير TEST_DATABASE_URL فريد لكل job). نصف يوم عمل.

عالية H-6: جلستان تكتبان نفس الشجرة — خطر حقيقي وقع فعلًا

خلال المراجعة: تعديلات متزامنة على نفس الملفات، commit التقط ملفات نصف مكتملة، وتشغيلان للاختبارات أفسد أحدهما قاعدة الآخر (37 فشلًا زائفًا). أُصلح العرض (عزل test.db) لكن السبب الجذري — لا يوجد بروتوكول تنسيق — باقٍ.

🔧 الإصلاح: فرع لكل جلسة + PR بدل الدفع المباشر لـ main، أو ملف LOCK/إشارة حجز. إجرائي لا كودي.

متوسطة M-1: اختبار عدم القابلية يثبت الرفض بالسبب الخطأ

اختبار Transaction UPDATE/DELETE ينجح لأن Prisma يرمي Foreign key violation قبل وصول الـ trigger — السلوك (الرفض) صحيح لكن الرسالة المُثبتة ليست رسالة الـ trigger. لو كُسر الـ trigger مستقبلًا، سيستمر الاختبار أخضرًا لنفس السبب الخطأ.

🔧 الإصلاح: تأكيد نص الخطأ يحتوي immutable عبر $executeRawUnsafe مباشرة بدل عميل Prisma.

متوسطة M-2: أدوات CLI معلقة في هذه البيئة (Prisma/npx)

prisma --version وnpx يعلقان هنا؛ المشروع يعمل بحلول بديلة (SQL عبر المحرك + ثنائيات مباشرة). هذا دين بيئي سيعض أي مساهم جديد.

🔧 الإصلاح: توثيق البدائل في CONTRIBUTING.md جديد + سكربت npm run doctor يفحص الأدوات (على غرار cubefarm).

متوسطة M-3: حدود معلنة تحتاج مراجعة قبل الإنتاج

MAX_MINOR ≈ 21M KW، وJWT_SECRET التطويري، وmock كمزود افتراضي — كلها موثقة وآمنة افتراضيًا (الفشل مغلق في الإنتاج)، لكن لا يوجد اختبار إقلاع-إنتاج يثبت رفض القيم الضعيفة.

🔧 الإصلاح: اختبار config.test.ts يثبت أن الإنتاج يرفض الأسرار الضعيفة.

منخفضة L-1: مخلفات وتحذيرات صغيرة

تحذير حجم الحزمة في بناء الويب (633KB — code-splitting لاحقًا)، ملف docs/phase2-review.html المؤقت، سجل _prisma_migrations قد يفتقد صف ledger (طُبق يدويًا)، و heuristics الـ mock الهشة (موثقة بصراحة كـ stub).

🔧 الإصلاح: تنظيف دفعي واحد + تثبيت سجل الـ migrations.

5 أفكار للإضافات المستقبلية 💡

اثنتا عشرة فكرة، مرتبة من الأقرب للأبعد — كل واحدة تُبنى على موجود.

1. إغلاق حلقة الجلسات (أسبوع)

توصيل runAgent ←→ AgentSession (H-2) + شاشة inspector تعرض الجلسة الحية. يحوّل المراقبة من لقطات إلى بث.

2. واجهات التنسيق الكاملة (أسبوع)

مسارات + شاشات + بذر لـ sessions/reviews/reports/escalations (H-4). أول مرة يرى فيها المالك عمل Phase 2 حقيقيًا.

3. ‏AgentWorkspace الحقيقي (Phase 3 §5–9)

مجلد معزول لكل وكيل + workspace.* + حارس المسارات. cubefarm أثبت النمط (desk = worktree).

4. محطة OpenCode (Phase 3 §15)

OpenCodeAdapter implements AIProvider — الوكيل يكتب كودًا حقيقيًا داخل مساحة عمله، والتنفيذ يبقى مُصرَّحًا ومدققًا.

5. بث حي WebSocket (Phase 3 §40)

استبدال الـ polling في الـ dashboard ببث session.output/tool/completed — نمط /ws موثق من cubefarm.

6. ذاكرة هجينة (Phase 3)

واجهة MemoryRetriever موجودة بالاسم — إضافة بحث شعاعي حقيقي خلفها مع metadata.embeddingRef المحجوز، مع بقاء الـ keyword كأساس حتمي.

7. رواتب ومشتريات تلقائية (Phase 2→3)

نبضة payroll من الخزينة + مشتريات السوق بمعدلات أسعار — أول اقتصاد يتحرك بذاته، وverifyLedger الليلي يحرسه.

8. وضع العرض Demo (صفر تكلفة)

backend وهمي على غرار cubefarm (--demo): GitHub وأحداث مزيفة — لتجربة الـ dashboard والعروض بدون مفاتيح ولا إنفاق.

9. تصدير التدقيق (Audit export)

تقرير امتثال بضغطة: كل الحركات + الموافقات + القرارات لفترة — يحوّل سجل التدقيق من مخزن إلى منتج.

10. اختبارات الفوضى (Chaos)

قتل عمليات mid-transfer، ملء القرص، ساعة مزيفة — إثبات أن «الفشل لا يُسقط العالم» ليس شعارًا.

11. تعدد الشركات والأسواق

المخطط يدعمها (مفاتيح مركبة عامة) — شركتان تتاجران عبر الخزائن، ثم سوق مركزي بأسعار.

12. المدينة ثلاثية الأبعاد (Phase 3 §44)

العقد جاهز (workspaceLocationId + أحداث) — العرض لاحقًا، والمنطق لا ينتظره.
